# Plan 02-01: CLI Subcommand Routing, Client & Service Queue Commands

## Goal
Implement the main executable entrypoint `cmd/peloton/main.go` and CLI command router supporting client management (`add`, `list`, `search`) and repair service ticket lifecycle operations (`add`, `list`, `status`). Output formatted human-readable ASCII tables.

## Proposed Changes

### Entry Point & Command Dispatcher (`cmd/peloton/main.go`, `internal/cli/root.go`)
- `main.go` handles flag parsing (`--db` custom path, `--version`, `--help`), initializes configuration and SQLite store, and delegates to subcommand handlers.
- Dispatcher commands:
  - `peloton client ...`
  - `peloton service ...`
  - `peloton finance ...`
  - `peloton version`
  - `peloton help`

### Client Subcommands (`internal/cli/client.go`)
- `peloton client add --name "Jan Kowalski" --phone "+48 500 600 700" [--bike "..."] [--notes "..."]`
- `peloton client list`: Tabular output (`ID`, `NAME`, `PHONE`, `BIKE`, `CREATED`)
- `peloton client search <term>`: Searches name, phone, or bike

### Service Ticket Subcommands (`internal/cli/service.go`)
- `peloton service add --client <id> --desc "Brake overhaul" [--priority Normal|High|Urgent] [--est 150.0]`
- `peloton service list [--status Pending|...]`: Tabular queue view (`#`, `CLIENT`, `PHONE`, `STATUS`, `PRIORITY`, `EST. COST`, `CREATED`)
- `peloton service status <ticket_id> <new_status> [--cost 160.0]`: Updates status with validation against domain lifecycle enums, records final cost, and logs completion timestamp.

### Testing (`internal/cli/cli_test.go`)
- Integration tests executing CLI command handlers with buffer capture (`bytes.Buffer`) against a temporary SQLite database.
- Verifying error codes on missing parameters and validating tabular output contents.
