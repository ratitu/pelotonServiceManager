# Plan 03-02: Ticket Detail Modal, In-Place Status Updates & Financial Summary Widget

## Goal
Implement the ticket inspection modal with in-place lifecycle transitions, embed the monthly financial balance widget into the TUI, and hook the TUI into `peloton` CLI (both via `peloton tui` subcommand and when no arguments are passed).

## Proposed Changes

### Ticket Detail & In-Place Status Advance (`internal/tui/detail.go`)
- Modal/popup overlay displaying:
  - Ticket ID, client name, phone, bike details
  - Full problem description & priority tag
  - Current status & estimated/final cost
  - Quick action keys:
    - `1` - Set to Pending
    - `2` - Set to In Progress
    - `3` - Set to Waiting for Parts
    - `4` - Set to Ready for Pickup
    - `5` - Set to Completed (prompts for final cost)
    - `Esc` / `q` / `Enter` - Return to board
- Status change immediately saves to SQLite via `TicketRepo.UpdateStatus` and updates the board column lists.

### Financial Summary Widget (`internal/tui/finance_widget.go`)
- Monthly cashflow overview card docked at the bottom/top of the screen or toggled via `m` / `f`:
  - Completed jobs count for current month
  - Total Income (+), Total Expenses (-)
  - Net Profit/Deficit indicator with colored badges (Green for Profit, Red for Deficit)
- Live updates when tickets are completed or financial entries are made.

### CLI Integration (`internal/cli/root.go`, `cmd/peloton/main.go`)
- Add `peloton tui` command to launch the Bubbletea interactive dashboard.
- Default behavior: when `peloton` is invoked with no CLI arguments in an interactive TTY, launch the TUI dashboard; if non-interactive or `--help` requested, print CLI usage.
